# Getting started

> Prepare your team for an initial AI assurance review

Use this section to complete your first governed review, starting with one well-defined AI use case instead of trying to import every AI tool in the organization.

## Prerequisites

| Requirement | Why it matters | Suggested owner |
| --- | --- | --- |
| Access to your Assurio environment | Enables your assigned workflow | Platform administrator |
| AI system description | Establishes what is being reviewed | System owner |
| Known baseline/version | Prevents evidence from being attached to the wrong configuration | Engineering lead |
| Applicable policies and risk criteria | Determines required controls and approval authority | Governance lead |
| Existing test artifacts | Provides initial evidence or reveals gaps | TEVV lead |
| Named decision authority | Prevents unowned acceptance | Governance sponsor |

> **Access and menus:** Confirm the sign-in URL, identity provider, tenant setup and labels shown in your actual Assurio deployment. Public product information does not establish exact onboarding screens or a self-service sign-up flow.

## Recommended sequence

1. Read [Quickstart](quickstart.md) for an end-to-end walkthrough.
2. Prepare the inventory fields in [Register an AI system](../guides/register-system.md).
3. Identify boundaries and controls in [Risk and impact assessment](../guides/risk-and-impact.md).
4. Attach available test results using [Evidence review](../guides/evidence-review.md).
5. Document an accountable decision through [Scoped approval](../guides/scoped-approval.md).
6. Define what changes require review with [Change and reassessment](../guides/change-reassessment.md).

## Outcomes of this section

By the end, you should be able to point to the current system baseline, responsible people, critical requirements, evidence gaps, a decision status and a change-review trigger. A first review may correctly end as **pending** or **restricted** when evidence is insufficient.
